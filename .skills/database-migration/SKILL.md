# Change the database schema

1. Inspect current models, `migrations/versions/`, `migrations/env.py` and production access paths before generating a revision.
2. Create a focused revision; review autogenerated SQL and remove unrelated drift.
3. Use expand/contract for destructive or locking changes: add compatible schema, backfill in bounded batches, switch readers/writers, then remove old schema in a later release.
4. Do not manually redefine LangGraph checkpoint tables unless the library contract explicitly requires it.
5. Set lock/statement timeouts where a production DDL operation can block traffic; preserve PgBouncer compatibility.
6. Verify upgrade SQL and behavior:

   ```bash
   alembic upgrade head --sql
   make db-upgrade
   alembic current
   ```

7. Test upgrade from the supported previous schema, application reads/writes, tenant isolation and rollback only when rollback is safe. Document irreversible data changes explicitly.

Never run downgrade or destructive migration against an unspecified environment.
